# 《饿了喵》游戏创意方案

版本：概念草案 v0.1  
整理日期：2026-10-14  
状态：用于讨论与美术探索，名称和数值均未定稿。

## 一句话概念

在一张严肃、精确的真实城市地图上，经营一家由小猫负责配送的外卖站。玩家认真规划路线，小猫认真制造意外。

## 一、定位与核心特色

- 类型：轻松的地图配送、调度策略与经营养成游戏。
- 玩家身份：猫咪配送站站长。
- 两个必要元素：与真实世界对应的地图底图；拥有性格、习惯与成长的小猫外卖员。
- 核心反差：专业导航与调度系统的严肃表达，搭配猫咪可爱、不可完全预测的行为。
- 单局目标体验：约 5—10 分钟，接单、派单、应对事件、结算形成完整循环。

地图必须保持真实城市地图的视觉与空间逻辑，保留路网、建筑轮廓、地名、缩放和比例尺。避免把地图改成童话城镇或卡通岛屿。猫咪以头像、定位点和轨迹出现在底图上，点开后才展示角色细节。

## 二、核心玩法循环

收到订单 → 挑选猫咪 → 安排取送顺序与路线 → 观察配送进展 → 处理途中事件 → 获得收入与信任 → 升级配送站、猫咪与装备。

一组订单示例：

| 订单 | 特点 | 决策重点 |
| --- | --- | --- |
| 面包店 → 写字楼 | 路程短、时效要求高 | 分配快速猫咪，减少交接等待 |
| 鱼汤店 → 小区 | 配送费高、香味明显 | 避免诱惑敏感猫，或使用密封装备 |
| 杂货店 → 公园 | 货物较重、时效宽松 | 交给负重猫，与顺路订单合并 |

初期玩家照看一只猫，后期协调多只猫的接力、拼单和休息。最短路线不一定是最快或最稳妥的路线。

## 三、真实地图如何参与玩法

第一阶段采用“玩家坐在家里指挥，猫咪在真实地图上跑”的模式。玩家选择熟悉街区开店，无需本人到达取送位置。配送距离与时间做游戏化压缩。

| 地图元素 | 游戏作用 |
| --- | --- |
| 真实道路 | 决定路径、绕行距离与拼单机会 |
| 建筑与地点 | 承载取餐点、顾客和配送站 |
| 河流与桥梁 | 形成路线瓶颈，影响跨区域接单 |
| 公园与绿地 | 提供休息机会，也可能让猫咪分心 |
| 游戏事件标记 | 标注纸箱、陌生狗、临时施工等状况 |

真实地点作为位置锚点，游戏店铺与订单可以使用虚构名称，例如商业区里的“胡须面馆”。游戏事件作为独立叠加层，避免与真实世界状态混淆。

猫咪头像、配送路线和订单状态是地图上的主要视觉信息。随着探索，可以切换猫咪图层：晒太阳热点、猫群活动范围、纸箱高发区等。

## 四、猫咪角色与配送策略

角色特点必须影响派单选择，而不只是外观或数值差异。

| 猫咪 | 配送优势 | 行为习惯 |
| --- | --- | --- |
| 橘猫「吨吨」 | 负重大，适合多单配送 | 闻到鱼香容易分心 |
| 狸花「闪电」 | 速度快，熟悉近路 | 容易跑过头，需要提前提醒 |
| 三花「老板」 | 交接效率高，善于安抚顾客 | 不喜欢与其他猫挤在同一取餐点 |
| 黑猫「夜班」 | 夜间配送稳定 | 白天需要更多休息 |

行为习惯应可提前了解、可应对。比如让吨吨送面包，或给它配密封保温箱。建立信任后，猫咪响应指令更快，但仍然保留性格。

## 五、途中事件与选择

意外应有征兆、有应对方式，避免纯随机惩罚。事件既能创造策略，也能留下故事。

示例：

> 路线异常：配送员停止移动。  
> 原因：发现高适配度纸箱。

玩家可选择：

1. 使用零食召回：消耗零食，立刻继续配送。
2. 允许休息片刻：增加配送时间，恢复精力。
3. 派附近猫咪接力：保持时效，占用另一只猫的运力。

纸箱可以在事后成为配送站家具，让事故偶尔带来收获。

其他事件包括：顾客想摸猫导致交接变慢；配送猫碰面互相闻了半天；突然下雨需要调整路线；配送员开始观察一只鸟。

## 六、订单故事

普通订单建立经营节奏，特殊订单让街区和顾客变得熟悉。故事通过订单备注、地图事件和完成后的短消息展开。

- “还是送到门口就好”：重复订餐的神秘顾客，原来是一只照顾小猫的猫妈妈。
- “别让面坨了”：挑剔的熟客，熟悉他的猫能提前通知他下楼，缩短交接时间。
- “这单不急”：跨越多个街区的生日蛋糕，需要几只猫接力配送。

## 七、长期成长

- 猫咪成长：学习技巧、培养信任、熟悉区域。
- 装备升级：保温箱、防雨披、不同容量的配送包。
- 配送站建设：休息窝、食堂、装备架，改善运转效率。
- 区域扩张：在更远街区设置分站，组织接力配送。

重点系统是“街区熟悉度”：猫在同一区域配送越多，越了解交接快的地方、休息点和容易遇到狗的路段。玩家与猫共同把一片街区送熟。

## 八、美术与表达原则

### 严肃地图，温暖小猫

底图采用克制的导航地图语言：浅灰建筑、清晰道路、低饱和绿地与水系；路线、状态、任务卡保持专业可读。猫咪和装备提供温暖颜色与角色感，不遮挡主要路网。

猫咪原画优先探索保留猫体态的角色：四足行动、背负轻量配送包，表情丰富。装备从小猫身体尺度出发，突出可辨识的轮廓。具体画风尚待概念图确认。

配送站可以温暖、有生活痕迹，包含订单票据、保温箱、纸箱窝和休息区；它通过独立场景或信息面板呈现，不把整张地图卡通化。

### 一本正经的幽默

> 预计送达时间已更新：14:32 → 14:39  
> 延迟原因：配送员正在观察一只鸟。  
> 观察进展：鸟尚未发现配送员。

订单结算包含双向评价：

> 顾客评价：汤很热，送得很快。  
> 猫咪评价：电梯有点可怕，但门口的地垫很好。

音效以订单与定位提示为主，配合少量猫叫，营造真实存在的猫咪配送系统的感觉。

## 九、第一版范围

- 一片真实街区。
- 三只可调度猫咪。
- 一个配送站。
- 三类订单。
- 五种途中事件。
- 跑通接单、派单、地图移动、事件处理、结算与基础升级。

最关键的验证问题：玩家是否会因为熟悉某只猫的脾气，主动改变派单或路线安排？如果会，猫咪就真正参与了策略。

## 十、待验证问题

- 真实道路与路径如何接入，采用哪一种地图服务与展示方式？
- 猫咪移动、订单倒计时与玩家操作的节奏如何平衡？
- 幽默事件的触发频率如何控制，避免重复和打断过多？
- 城市之间的道路差异，能否形成不同配送体验？
- 原画中角色的可爱程度与严肃地图的视觉反差是否协调？

以上为后续设计与原型验证问题，尚不代表已确定的技术实现。
