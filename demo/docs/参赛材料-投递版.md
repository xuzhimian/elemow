## 有价值的反馈（用 AI 工具做地图应用）

1. **坐标系必须人来兜底**：OSM 是 WGS-84、腾讯是 GCJ-02，国内偏差数百米。建议把「坐标系」做成 SDK 一等公民，提供显式标记与自动转换。
2. **SDK 隐式行为只能靠跑起来看**：`boundary` 是 cover 语义（曾让区域左右各溢出 357 px）；`borderWidth: 0` 或线宽 ≤4 带虚线时**整条线不绘制**；SDK 注入的 `z-index: 1000` 事件层若无层叠上下文会逃逸，曾导致全站按钮失效。建议写成「已知行为」文档或加运行时告警。
3. **警惕假阴性验证**：我写 `v.lng ?? v[0]` 读锚点，实际结构是 `{node}`，读到 `undefined` 使比较恒为 false，打印出漂亮的「越界 0/18」，真相是 13/18 越界；同类问题第二次是 `AREA_LOCAL` 缺 `width` 导致约束全变 `NaN` 静默失效。建议为数据校验加一层**结构断言**。
4. **外部依赖不可靠就预烘焙**：Overpass 公共镜像限流严重，改为离线固化路网（约 45 KB），运行时零依赖、结果稳定。建议官方提供「离线路网包」导出能力。
5. **降级要沿语义优先级**：腾讯路线 → OSM 路网 → 示意网格 → 灰盒，每级都标注「你正在看什么、与真实差多少」。建议把「降级可见性」做成通用能力。
6. **设想落规则是 AI 强项**：「命名贴合真实环境」落成标签归类 → 加权投票 → 约束分配 → 词根加后缀，包括权衡（收紧间距会让独居老奶奶落进餐饮区，遂引入 `strict` 优先占位）。
7. **工具摩擦**：本地清理的 `rm`/`pkill` 反复触发审批超时，拖慢回归节奏；建议为明确的本地验证动作提供免审批通道。
